1. Introduction

In modern higher education environments, university students, faculty, and visiting scholars must navigate hundreds of disparate academic policies, complex syllabi, volatile examination calendars, and faculty office schedules. Students often spend valuable hours contacting administrative desks or searching across multi-page portal PDFs to obtain straightforward information such as syllabus modules, prerequisites, GPA calculations, and test weightages.

CampusMind AI is an intelligent conversational agent engineered to bridge this gap. Utilizing Natural Language Processing (NLP), TF-IDF vectorization, semantic similarity scoring, and context-aware dialogue management, CampusMind AI delivers instant, authoritative, and multi-turn academic advisory assistance through an accessible web interface.

2. Problem Statement

Traditional campus inquiry channels suffer from substantial bottlenecks:

  • Information Dispersion: Academic catalogs, syllabi, grading policies, and exam notices reside in fragmented portals and static PDFs.
  • High Administrative Burden: Department heads and administrative staff are repeatedly burdened with routine inquiries (e.g., attendance thresholds, pass marks, room locations).
  • Lack of 24/7 Responsiveness: Students studying during late-night hours or prior to examinations cannot obtain real-time clarification.

Proposed Solution: Build a high-availability, modular AI chatbot system that ingests academic curriculum data, interprets user natural language questions with confidence scoring, preserves conversational context across dialogue turns, and delivers instant, interactive responses with voice capability.

3. Functional Requirements (FR)

The system is architected into three primary functional modules fulfilling the VITyarthi requirements:

Module Requirement ID Description & Capabilities
Module 1: NLP & Intent Classification FR-1.1 Text normalization, tokenization, punctuation stripping, and stopword filtering.
FR-1.2 TF-IDF vectorization and Cosine Similarity intent classification across 12 distinct intents with confidence thresholding.
FR-1.3 Academic entity extraction (Course codes e.g. CS101, semester tokens, faculty names, exam types).
Module 2: Dialogue & Knowledge Management FR-2.1 Multi-turn context retention (tracking active course, active semester across conversation turns).
FR-2.2 Hierarchical academic repository search (course syllabi, schedules, grading criteria, campus services).
FR-2.3 Dynamic query suggestions generator and fallback topic matching.
Module 3: Web Presentation & Telemetry FR-3.1 Responsive glassmorphism web interface with dark/light themes and quick prompt chips.
FR-3.2 Speech-to-Text (STT) voice dictation and Text-to-Speech (TTS) voice read-aloud via Web Speech API.
FR-3.3 Real-time telemetry tracking (query counts, latency, intent distribution, satisfaction rating).

4. Non-Functional Requirements (NFR)

  • NFR-1 (Performance & Latency): Query processing and intent classification must respond within $\le 150\text{ ms}$ on standard server hardware.
  • NFR-2 (Usability & Accessibility): Responsive layout adhering to WCAG guidelines, dark/light themes, keyboard shortcuts, and voice accessibility.
  • NFR-3 (Reliability & Robustness): Graceful degradation with fallback handlers for unrecognized queries with low confidence scores ($< 0.22$).
  • NFR-4 (Maintainability & Modularity): Decoupled architecture across 8+ focused modules adhering to single-responsibility principles with $>80\%$ unit test coverage.

7. Design Decisions & Rationale

  • Standard-Library TF-IDF vs. Heavy Neural Transformers: A key engineering decision was implementing a pure Python TF-IDF and Cosine Similarity engine rather than multi-gigabyte models like PyTorch/HuggingFace BERT. This ensures sub-20ms inference times, zero hardware dependency hurdles, and instantaneous cold-boot times.
  • Session State In-Memory with SQLite Mirroring: Fast runtime state transitions happen in Python memory while every turn is asynchronously mirrored to SQLite for durability and evaluation telemetry.
  • Web Speech API Integration: Incorporating native browser STT and TTS provides hands-free accessibility for students without demanding third-party cloud billing APIs.

8. Implementation Details

The implementation resides entirely within clean, modular directories:

  • nlp/preprocessor.py: Custom tokenization and stopword removal preserving intent-critical inquiry terms (what, when, where, who).
  • nlp/intent_classifier.py: Centroid vectorization across 12 intent classes with threshold-guarded fallback.
  • nlp/entity_extractor.py: Regular expression token recognition for course codes (e.g., CS101, CS201, MAT101).
  • core/dialogue_manager.py: Multi-turn context carryover enabling natural follow-up queries (e.g. asking "Who teaches it?" immediately after discussing CS201).
  • models/database.py: Schema initialization and thread-safe SQLite connection management.

9. Verification & Results

Validation Summary:
All unit tests for tokenization, intent recognition, entity extraction, and API endpoints pass with 100% success rate. The server runs locally on http://127.0.0.1:5000 with average query latency under 25 milliseconds.

10. Testing Approach

Testing encompasses unit testing and API integration testing executed via pytest:

  • NLP Unit Tests: Validate tokenization, lowercasing, stopword stripping, and n-gram calculation.
  • Intent & Confidence Tests: Validate intent accuracy for greetings, course inquiries, syllabus questions, exam dates, and low-confidence fallback behavior.
  • Knowledge Base Tests: Verify course catalog retrieval, syllabus integrity, and policy lookups.
  • API Integration Tests: Test endpoints /api/chat, /api/analytics, and /api/feedback for valid status codes and JSON payloads.

11. Challenges Faced

  • Conversational Ambiguity: Distinguishing between asking for a general course description vs. an in-depth module syllabus was resolved through entity-assisted intent refinement.
  • Multi-Turn Context Tracking: Users frequently use pronouns (e.g. "who teaches it?"). This was addressed by maintaining session context variables (active_course).

12. Learnings & Key Takeaways

  • Mastery of fundamental NLP vectorization concepts (Term Frequency, Inverse Document Frequency, and Vector Dot Products).
  • Understanding how dialogue state managers bridge raw NLP classification with business logic and database persistence.
  • Designing modern, accessible web interfaces that combine visual aesthetics with assistive speech technology.
